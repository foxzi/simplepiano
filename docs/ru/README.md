# Simple Piano — документация (русский)

Небольшое веб-приложение для изучения основ фортепиано: 32 страницы
уроков, покрывающих все 48 тем программы, тренажёр гаммы до мажор и
справочник теории, с опциональной поддержкой MIDI-клавиатуры. Не требует
установки зависимостей на стороне пользователя. Построено на Vue 3 и Vite,
с тремя переключаемыми темами оформления (светлая, тёмная, тетрадь).

## Запуск приложения

Приложение — это проект на Vue 3 + Vite (`src/`, `index.html`,
`vite.config.js`). Все зависимости устанавливаются и запускаются внутри
Docker — `npm install` на хосте не требуется.

Сервер для разработки (с горячей перезагрузкой):

```bash
git clone https://github.com/foxzi/simplepiano.git
cd simplepiano
docker compose up -d
```

Эта команда собирает образ на основе `node:22-alpine`, устанавливает
зависимости внутри контейнера и запускает dev-сервер Vite, доступный на
`127.0.0.1:5174` на хосте (проброшен на порт `5173` внутри контейнера).
Откройте `http://127.0.0.1:5174/` в браузере. Остановить контейнер:
`docker compose down`.

Продакшн-сборка (результат попадает в `dist/`):

```bash
docker compose run --rm app npm run build
```

Dev-сервер привязан только к `127.0.0.1` на хосте — из соображений
безопасности. Если порт 5174 уже занят другим проектом на вашей машине,
измените порт хоста в `compose.yaml` (секция `ports:`).

`compose.yaml` описывает только среду разработки: он запускает `npm run
dev`. Для публичной раздачи есть отдельный `Dockerfile.prod` — он собирает
приложение и копирует `dist/` в образ nginx:

```bash
docker build -f Dockerfile.prod -t simple-piano .
docker run -d -p 8080:80 simple-piano
```

Маршрутизация в приложении построена на хеше URL (`#/lesson/...`), поэтому
никаких правил переадресации на `index.html` веб-серверу не требуется.
HTTPS — задача обратного прокси перед этим контейнером; Web MIDI в Chrome
работает только в защищённом контексте, то есть по HTTPS или с localhost.

Однофайловая офлайн-сборка (результат — `dist-offline/simple-piano.html`,
открывается без сервера и без интернета) описана ниже в разделе
«Офлайн-сборка (один файл)».

## Офлайн-сборка (один файл)

Кроме обычной продакшн-сборки есть команда, которая собирает приложение в
один самодостаточный HTML-файл:

```bash
docker compose run --rm app npm run build:offline
```

Команда запускает `vite build` с переменной окружения `OFFLINE_BUILD=1`. В
`vite.config.js` эта переменная включает `base: "./"` и снимает ограничение
`assetsInlineLimit`, поэтому все ресурсы, включая шрифты, попадают в CSS в
виде `data:` URI. Сборка идёт в каталог `dist-offline/`, после чего скрипт
`scripts/build-offline.mjs` вставляет получившиеся JS и CSS прямо внутрь
HTML и удаляет промежуточные файлы. В результате получается один файл
`dist-offline/simple-piano.html` размером около 564 КБ.

Такой файл открывается двойным кликом из файлового менеджера (протокол
`file://`), без веб-сервера. Инлайнинг необходим, потому что браузер не
выполняет внешние `<script type="module" src="...">` при открытии страницы
по `file://` (ограничения CORS, origin `null`) — весь код должен быть внутри
самого HTML.

Проверено фактически в headless Chrome при открытии
`dist-offline/simple-piano.html` по `file://` без доступа к сети: приложение
отрисовывается, ошибок в консоли нет, `window.isSecureContext === true`,
`navigator.requestMIDIAccess` доступен (то есть MIDI-клавиатуры работают),
Web Audio работает, `localStorage` работает (сохраняются тема, прогресс
уроков и выбор количества кругов).

Как и везде, Web MIDI поддерживается только в Chrome и других браузерах на
Chromium — в Firefox и Safari Web MIDI недоступен независимо от способа
запуска (подробнее в разделе «Web MIDI: HTTPS/localhost и ограничения
браузеров» ниже).

Каталог `dist-offline/` добавлен в `.gitignore`. Обычная сборка
(`npm run build`) и режим разработки (`npm run dev`) не изменились — там
шрифты по-прежнему подключаются как отдельные файлы `.woff2`.

## Web MIDI: HTTPS/localhost и ограничения браузеров

Web MIDI API (`navigator.requestMIDIAccess`) доступен только в
**безопасном контексте**. На практике это означает одно из:

- страница раздаётся по `https://`, либо
- страница раздаётся по `http://localhost` / `http://127.0.0.1`.

Раздача по обычному `http://` на IP-адресе локальной сети (например,
`http://192.168.x.x`) **не сработает** — браузер не предоставит
`navigator.requestMIDIAccess`, либо метод будет заблокирован при вызове.
Dev-сервер Vite, запущенный через `docker compose up -d`, доступен по адресу
`http://127.0.0.1:5174` — это удовлетворяет требованию безопасного
контекста, поэтому HTTPS-сертификат для локального тестирования не нужен.

Поддержка в браузерах также различается:

- Chrome, Edge, Opera и другие браузеры на Chromium поддерживают Web MIDI.
- У Firefox и Safari исторически была ограниченная поддержка или её не было
  вовсе (проверьте актуальное состояние для конкретной версии браузера,
  прежде чем полагаться на поддержку).
- Приложение определяет оба случая (API отсутствует или небезопасный
  контекст) и отключает кнопку «Подключить MIDI» с поясняющим сообщением
  вместо тихого падения.

Приложение запрашивает доступ к MIDI **без** SysEx (`{ sysex: false }`), это
упрощает запрос разрешения и полностью достаточно для сообщений
note on/off.

## Темы оформления

В переключателе тем в шапке доступны три доступные (accessible) темы:
светлая, тёмная и «тетрадь» (тёплый, похожий на бумагу вид). Выбранная тема
сохраняется в `localStorage` и восстанавливается при следующем визите;
нужная тема применяется до первой отрисовки, чтобы избежать мигания
неверной темой. Если сохранённого предпочтения ещё нет, приложение
опирается на системную настройку `prefers-color-scheme` браузера.

## Языки

Рядом с переключателем тем стоит переключатель языка: RU, EN, ES.
Переводятся не только надписи интерфейса, но и все 32 урока, теория и
названия нот (До / C / Do). Выбор сохраняется в `localStorage` под ключом
`pianoL.locale.v1`; при первом визите язык берётся из настроек браузера,
а если подходящего нет — остаётся русский.

Структура уроков (ноты, типы практик, нотный стан) описана один раз, а
переводы накладываются поверх неё. Подробности и формат пакетов перевода —
в [I18N.md](./I18N.md).

## Шрифты

Шрифты вшиты в приложение локально и не загружаются из интернета. Раньше
они подключались через Google Fonts (`<link>` и `preconnect` в
`index.html`); теперь эти теги удалены, а файлы шрифтов лежат прямо в
репозитории, в `src/assets/fonts/` (9 файлов `.woff2`, суммарно около
147 КБ), и объявлены в `src/fonts.css`, который импортируется в
`src/main.js` перед `src/style.css`. Состав:

- Fraunces Variable (латиница);
- Manrope Variable (латиница и кириллица);
- IBM Plex Mono, начертания 400/500/600 (латиница и кириллица).

Шрифты взяты из пакетов `@fontsource`, лицензия — OFL. Fraunces не содержит
кириллицы (её нет в самом шрифте), поэтому для русских заголовков
используется запасной шрифт Georgia — так было и при подключении через
Google Fonts, поведение не изменилось. Тема «тетрадь» (по умолчанию)
намеренно использует Georgia/Iowan Old Style, а Manrope и Fraunces
применяются в темах «светлая» и «тёмная».

Благодаря локальным шрифтам приложению больше не нужен интернет — ни для
обычной сборки и дев-сервера, ни тем более для офлайн-сборки (см. раздел
«Офлайн-сборка (один файл)» выше).

## Проверка на физическом MIDI-оборудовании не проводилась

Приложение было реализовано и проверено продакшн-сборкой
(`docker compose run --rm app npm run build`) в среде без подключённой
физической MIDI-клавиатуры. Код работы с MIDI (`requestMIDIAccess`, выбор
входа, `onmidimessage`, `onstatechange`) следует стандартному контракту Web
MIDI API, но **не проходил** сквозное тестирование на реальном
оборудовании. Перед тем как полагаться на эту функцию, проверьте её с
реальной MIDI-клавиатурой/синтезатором и сообщите об особенностях
конкретных устройств (например, running status, нестандартная разбивка
сообщений), если они встретятся.

Клавиатура на экране и все функции, не связанные с MIDI (синтезатор на Web
Audio, логика упражнения, метроном, уроки теории, сохранение в
localStorage), не зависят от оборудования и были опробованы в браузере в
процессе разработки.

## Тембр инструмента

В панели внизу экрана, в блоке «Настройки: MIDI, тембр, звук», есть
выпадающий список «Инструмент» с
шестью пресетами (аддитивный синтез: набор гармоник + огибающая ADSR +
опциональный фильтр нижних частот с собственной огибающей яркости):

- «Фортепиано» (`piano`) — тембр по умолчанию, ударный звук с затуханием.
- «Электропиано» (`epiano`) — мягкий колокольчиковый звук в духе родес-пиано.
- «Орган» (`organ`) — звук держится ровно, пока нажата клавиша.
- «Струнные» (`strings`) — плавное нарастание и долгое послезвучие.
- «Музыкальная шкатулка» (`musicbox`) — короткий звонкий звук.
- «Простой синтезатор» (`synth`) — исходный тон приложения: один треугольный
  осциллятор без затухания.

Пресеты описаны в `src/constants/instruments.js`. У «Фортепиано» и
«Музыкальной шкатулки» верхние ноты дополнительно затухают быстрее нижних
(поле `decayPitchSemitones`), как у акустических инструментов. При смене
инструмента сразу проигрывается нота до₄, чтобы услышать тембр, а под
списком показывается короткая подсказка о его характере. Выбор
сохраняется в `localStorage` под ключом `pianoL.instrument.v1` и
восстанавливается при следующем визите. Звук метронома не зависит от
выбранного инструмента. Никаких аудиосэмплов не используется — весь звук
синтезируется в браузере через Web Audio API.

### Нотная запись

Уроки со чтением нот показывают настоящий нотный стан — компонент
`src/components/MusicStaff.vue` рисует его на SVG: скрипичный и басовый
ключ, добавочные линии, целые, половинные, четвертные и восьмые ноты с
точками, паузы, знаки альтерации и тактовые черты. Ноты подсвечиваются
синхронно с ходом практики, поэтому видно, какой такт играется сейчас.

Клавиатура, метроном, выбор тембра и настройки MIDI вынесены в общую панель
внизу экрана (`.workbench` в `App.vue`) — она одинакова на всех страницах,
поэтому клавиатура всегда под рукой.

Панель сворачивается кнопкой в её заголовке, чтобы освободить место для
нотного стана и текста урока. Выбор хранится в localStorage
(`pianoL.workbench.v1`, `src/composables/useWorkbench.js`) и меняется только
этой кнопкой: игра на подключённой MIDI-клавиатуре свёрнутую панель не
разворачивает. Ноты при этом засчитываются в практике как обычно — панель
нужна только для экранной клавиатуры и настроек.

### Типы практических заданий

Движок заданий — `src/composables/useLessonTask.js`, тип задаётся полем
`type` в описании практики:

- `explore` — нажать заданное количество разных клавиш (свободное
  знакомство, ошибок не бывает);
- `set` — найти набор нот в любом порядке (например, все До на клавиатуре);
- `sequence` — сыграть ноты строго по порядку; неверная нота увеличивает
  счётчик ошибок, но не сбрасывает прогресс;
- `rhythm` — то же, что `sequence`, но каждая нота должна попадать в щелчок
  метронома: допуск — 35 % длительности доли, и на одну долю засчитывается
  только одна нота;
- `chord` — взять аккорд целиком: ноты должны звучать одновременно,
  проверка срабатывает, когда все клавиши аккорда зажаты вместе;
- `ear` — задание на слух: приложение играет опорную ноту и вторую,
  нужно найти вторую на клавиатуре; число вопросов задаётся полем `rounds`.

Дополнительные поля практики:

- `noHints` — не подсвечивать клавиши (чтение с листа, игра по памяти);
- `requireBpm: { min, max }` — задание засчитывается только при метрономе
  в указанном диапазоне темпа;
- `labels` — подписи на клавишах (аппликатура, ступени);
- `chordNames` — названия аккордов, которые показываются по шагам;
- `staff` — нотная строка, которую рисует `MusicStaff.vue`.

Нужные клавиши подсвечиваются на общей клавиатуре (жёлтая точка), уже
сыгранные — зелёным. У заданий с аппликатурой на клавишах показываются
номера пальцев.

### Количество кругов

Задания короткие, поэтому у каждого из них есть селектор «Кругов»:
1, 2, 3, 5 или 8. Задание нужно пройти выбранное число раз подряд, и только
после последнего круга оно считается выполненным. Между кругами счётчик
шагов обнуляется, а ошибки продолжают копиться — полоса прогресса и строка
«Круг N из M» показывают общий ход.

Выбор сохраняется отдельно для каждой практики в `localStorage` под ключом
`pianoL.repeats.v1` (формат `{"id-урока:id-практики": 3}`), поэтому после
перезагрузки настройка остаётся. Менять число кругов можно только когда
задание не запущено.

### Прогресс по урокам

Урок считается пройденным, когда выполнены все его практики. Список
пройденных уроков хранится в `localStorage` под ключом
`pianoL.lessons.v1` (формат `{"completed": ["keyboard-tour", ...]}`).
На оглавлении показывается общий прогресс и кнопка «Продолжить» с первым
непройденным уроком; результат старого тренажёра гаммы по-прежнему хранится
отдельно под ключом `pianoL.progress.v1`.

## Упражнение: гамма до мажор, одна октава

- Ноты (номера MIDI): до4=60, ре4=62, ми4=64, фа4=65, соль4=67, ля4=69,
  си4=71, до5=72 — восходящая гамма до мажор в пределах одной октавы.
- Приложение ждёт правильную следующую ноту, прежде чем продвинуться дальше;
  неверные ноты засчитываются как ошибки, но не блокируют прогресс.
- MIDI-сообщение «note on» с velocity, равным 0, согласно спецификации MIDI
  трактуется как «note off», поэтому оно не продвигает упражнение.
- Перед началом можно выбрать аппликатуру для правой или левой руки
  (отображается для каждой ноты).
- Прогресс, количество ошибок и результат прохождения сохраняются в
  `localStorage` (обёрнуто в try/catch — если хранилище недоступно, например
  в режиме инкогнито, приложение аккуратно продолжает работу и сообщает,
  что результат не сохранён).
- Запись о прохождении сохраняется только после того, как все 8 нот
  реально сыграны верно по порядку — никакого «фиктивного» успеха нет.

## Ограничения

- Отдельный тренажёр на странице `#/scale` охватывает только одну гамму
  (до мажор, одна октава, восходящее движение); остальные гаммы разобраны
  в уроках модуля «Гаммы и тональности».
- Педаль и динамика объясняются и тренируются на слух: приложение не читает
  MIDI-контроллер педали (CC 64) и не оценивает силу нажатия (velocity).
- Звук — аддитивный синтез (см. «Тембр инструмента»), а не сэмплированное
  настоящее фортепиано.
- Переключатель звука Web Audio влияет только на ноты, приходящие с
  подключённого MIDI-устройства (чтобы не дублировать звук, если у
  оборудования есть собственный синтезатор). Клики по клавиатуре на экране и
  демонстрация гаммы всегда воспроизводят звук после действия пользователя —
  так требуют политики автовоспроизведения браузеров.
- Нет бэкенда, аккаунтов и аналитики — всё работает в вашем браузере.

## Если нет звука

В панели внизу экрана есть кнопка «Проверить звук» и индикатор
состояния аудио. Нажмите кнопку — должна прозвучать нота ля₄ длиной около
секунды, а индикатор перейти в состояние «работает».

| Индикатор | Что это значит |
| --- | --- |
| работает | Web Audio запущен, звук идёт в системный аудиовыход |
| заблокирован браузером | Контекст ещё не разбужен — нажмите «Проверить звук» или любую клавишу |
| браузер не поддерживает Web Audio | Нужен современный браузер (Chrome, Edge, Safari, Firefox) |
| ошибка | Текст ошибки браузера показывается под индикатором |

Если индикатор показывает «работает», но звука нет — причина вне приложения:
проверьте системную громкость, микшер (громкость именно вкладки браузера),
выбранное устройство вывода и то, что вкладка не заглушена.

Щелчки по экранным клавишам, демонстрация гаммы и метроном звучат всегда.
Переключатель «Звук синтезатора для MIDI» влияет только на ноты, приходящие
с внешней MIDI-клавиатуры.

## Если MIDI-клавиатура не звучит

1. Убедитесь, что в блоке «Настройки: MIDI, тембр, звук» включён переключатель
   «Звук синтезатора для MIDI» — по умолчанию он выключен, чтобы не дублировать
   собственный звук инструмента.
2. Если у самого инструмента нет встроенного синтезатора (обычные MIDI-контроллеры
   без звука), этот переключатель обязателен.
3. Проверьте, что в статусе подключения указано имя вашего устройства; при
   подсветке клавиш на экране MIDI-сигнал принимается корректно.
4. Проверьте системную громкость и то, что вкладка браузера не заглушена.
